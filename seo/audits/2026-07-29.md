## 2. Accessibility pass — executed (partial, safe subset)

Backlog item (PageSpeed: Accessibility 81 mobile / 84 desktop, not yet
triaged). Triaged all four named issues; fixed the three that are pure
technical/markup fixes with zero visual risk, left the one that's a design
call.

**Fixed, verified via local preview (computed styles + DOM inspection,
screenshots inconclusive due to the site's scroll-reveal/scroll-scrub JS not
firing on programmatic `scrollTo`, so verification leaned on
`preview_inspect` computed-style checks instead):**

1. **No `<main>` landmark** — page had `<body>` → `<nav>` → bare content →
   `<footer>`, no landmark wrapping the primary content at all. Added
   `<main id="main-content">` around everything between the mobile-book-bar
   and the closing `</section>` of the booking form (i.e. hero through book
   section; nav/rail/footer/WhatsApp FAB stay outside, correctly). Verified:
   `document.querySelector('main')` exists with 12 direct children, no CSS
   targets `<main>` by tag so no visual change.
2. **Booking-form labels had no programmatic association with their inputs**
   — `<label>Your name</label>` and `<input name="name" .../>` were visual
   siblings only (no `for`/`id`, no wrapping). A screen reader announces
   these inputs with no name. Added matching `id`/`for` pairs for the 5
   affected fields: name, WhatsApp, email, event date, venue (package and
   event-type `<select>` already had `id`s but their `<label>`s were missing
   `for` — fixed those too, for 7 total). Addon checkboxes were already
   correctly wrapped in `<label>` (no fix needed there). Verified via
   `preview_eval`: all 7 `for` attributes resolve to an existing element by
   `id`; verified via `preview_inspect` that label/input positioning, font
   size and color are pixel-identical to before (nothing depends on the
   `for` attribute for layout).
3. **Heading order skip** (`<h2>Feel the film yourself.</h2>` → `<h4>Try the
   filter live</h4>`, jumping past `<h3>`) in the live-filter-demo section.
   Changed the `<h4>` to `<h3>` **and** its paired CSS selector
   (`.demo .status h4` → `.demo .status h3`) in the same edit, so the visual
   style (italic, 32px, cream color, Fraunces font) travels with it exactly.
   Verified via `preview_inspect`: computed styles on the new `<h3>` match
   the old `<h4>` rule exactly (font-size 32px, font-style italic, color
   rgb(246,232,222)).
