## 3. New gap found and fixed: `/catalogue/` pages

The AI style and video catalogues shipped 2026-09-08 (commit `94133e5`,
outside this loop) and were already in `sitemap.xml`, but weren't part of
any prior SEO audit. Checking them turned up a real, fixable gap:

- **`/catalogue/`** itself was a 95-byte client-side meta-refresh stub
  (`<meta http-equiv="refresh" content="0;url=ai-styles.html">`) with no
  `<title>`, no meta description, no OG tags — yet it was the URL listed in
  `sitemap.xml` at **priority 0.8** (higher than `/software/`).
- **`catalogue/ai-styles.html`** (the actual content, 24 curated AI styles)
  had its `<link rel="canonical">` pointing *back* to that empty stub
  instead of itself — while **`catalogue/videos.html`** correctly
  self-canonicalized. Inconsistent signal for crawlers: one real content
  page said "the canonical URL is a page with nothing on it."
- Neither catalogue page had a meta description or Open Graph/Twitter
  tags — a shared link would have rendered with no snippet/preview.

**Fixed this iteration** (branch `seo-improvements-8`):

1. `vercel.json` — added a proper 308 redirect: `/catalogue` and
   `/catalogue/` → `/catalogue/ai-styles.html`. Replaces reliance on the
   meta-refresh for crawlers (meta refresh is inconsistently treated by
   search engines; a real HTTP redirect is unambiguous). The stub HTML file
   is left in place untouched as a harmless fallback if the redirect config
   is ever removed.
2. `catalogue/ai-styles.html` — canonical corrected to point to itself
   (`https://playingwithphoto.com/catalogue/ai-styles.html`); added a meta
   description and full OG/Twitter card tags, reusing the site's existing
   `og-hero-2026.jpg` share image (no new image judgment call — this is
   already the site-wide default share image).
3. `catalogue/videos.html` — added the same meta description + OG/Twitter
   tags (canonical was already correct, untouched).
4. `sitemap.xml` — `/catalogue/` entry replaced with
   `/catalogue/ai-styles.html` to match the corrected canonical, same
   priority (0.8), `lastmod` bumped to today.

All meta description copy was drawn directly from existing on-page text
("24 curated transformations" / "6 motion-ready styles" wording already in
each page's `<h1>`/intro) — no new claims invented. `vercel.json` and
`sitemap.xml` both re-validated as syntactically correct (JSON parse, XML
parse) after editing.
